Data Flow Diagram

5 minutos

Definición: Representación gráfica del flujo de datos a través de un sistema de información

Elementos del DFD

⬜

Entidades Externas

Fuentes o destinos de datos externos al sistema

Usuario, Cliente, Sistema externo
⭕

Procesos

Transformaciones de datos

Validar usuario, Calcular total, Generar reporte
═══

Almacenes de Datos

Almacenes de datos

Base de datos, Archivo, Cache
→

Flujos de Datos

Movimiento de datos entre elementos

Datos usuario, Confirmación, Reporte

Niveles de DFD

Nivel 0 (Context)

Vista general del sistema completo - Un solo proceso que representa todo el sistema

Nivel 1

Descomposición del proceso principal - Procesos principales del sistema

Nivel 2+

Descomposición detallada - Sub-procesos y detalles específicos

Reglas de Construcción

  • Un DFD no puede tener flujos entre entidades externas
  • Un DFD no puede tener flujos entre almacenes de datos
  • Todo proceso debe tener al menos una entrada y una salida
  • Los nombres de flujos deben ser sustantivos
  • Los nombres de procesos deben ser verbos

Wireframe Diagram

5 minutos

Definición: Representación visual esquemática de la estructura y elementos de una interfaz

Baja Fidelidad

Características: Esquemáticos, Sin colores, Tipografía básica, Placeholders

Herramientas: Papel y lápiz, Balsamiq, POP

Cuándo usar: Etapas iniciales, brainstorming

✅ Ventajas:
  • Rápido
  • Económico
  • Fácil modificación
❌ Desventajas:
  • Poca interactividad
  • Feedback limitado

Alta Fidelidad

Características: Detalles finales, Colores reales, Imágenes, Interacciones

Herramientas: Figma, Adobe PS y XD, InVision, Framer

Cuándo usar: Testing final, handoff a desarrollo

✅ Ventajas:
  • Representación real
  • Testing preciso
❌ Desventajas:
  • Tiempo considerable
  • Mayor costo

Proceso de Wireframing

1

Definir objetivos

Establecer propósito y audiencia

2

Investigar

Analizar competencia y mejores prácticas

3

Mapear flujos

Definir user journeys principales

4

Crear wireframes digitales

Desarrollar versiones digitales detalladas

High Fidelity and Low Fidelity Diagram

8 minutos

Low Fidelity

Características Visuales

  • Colores: Escala de grises o monocromático
  • Tipografía: Placeholder text o tipografía genérica
  • Imágenes: Cajas grises o X marcando posición
  • Layout: Estructura básica con espaciado aproximado

Nivel de Interacción

  • Elementos clickeables limitados
  • Navegación básica, principalmente estática
  • Formularios solo estructura
  • Sin animaciones

High Fidelity

Características Visuales

  • Colores: Paleta de colores final
  • Tipografía: Fuentes específicas y jerarquía tipográfica
  • Imágenes: Imágenes reales o muy similares
  • Layout: Espaciado y medidas exactas

Nivel de Interacción

  • Elementos totalmente funcionales
  • Flujos completos e interactivos
  • Formularios con validaciones
  • Transiciones y microinteracciones

Criterios de Selección

Fase del Proyecto

  • Exploración temprana: Baja fidelidad
  • Validación de conceptos: Media fidelidad
  • Validación final: Alta fidelidad

Recursos Disponibles

  • Tiempo limitado: Priorizar baja fidelidad
  • Presupuesto limitado: Combinar baja y media
  • Recursos completos: Proceso completo

Tipo de Audiencia

  • Equipo técnico: Baja fidelidad suficiente
  • Stakeholders de negocio: Media a alta preferible
  • Usuarios finales: Alta fidelidad para testing

Database Schema Design Diagram

4 minutos

Definición: Estructura que define la organización, relaciones y restricciones de datos en una base de datos

Diseño Conceptual

Propósito: Vista de alto nivel independiente de tecnología

Elementos: Entidades, Atributos, Relaciones

Output: Diagrama Entidad-Relación (ER)

Audiencia: Analistas de negocio, stakeholders

Diseño Lógico

Propósito: Estructura lógica sin detalles físicos

Elementos: Tablas, Campos, Llaves primarias/foráneas, Restricciones

Output: Esquema lógico normalizado

Audiencia: Diseñadores de BD, desarrolladores

Diseño Físico

Propósito: Implementación específica en SGBD

Elementos: Tipos de datos específicos, Índices, Particiones, Storage

Output: Scripts DDL

Audiencia: DBAs, administradores de sistema

Componentes del Diagrama ER

⬜

Entidades

Customer, Order, Product

⭕

Atributos

Simple, Composite, Derived, Multi-valued

◇

Relaciones

1:1, 1:N, N:M cardinalities

Normalización

1NF: Eliminar grupos repetitivos
2NF: Eliminar dependencias parciales
3NF: Eliminar dependencias transitivas
BCNF: Forma normal de Boyce-Codd

Herramientas de Diseño

MySQL Workbench

Forward/Reverse engineering, Visual query builder

DbSchema

Multi-database support, Team collaboration

Erwin Data Modeler

Enterprise features, Governance tools
